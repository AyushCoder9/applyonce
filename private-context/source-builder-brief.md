# Original builder brief captured for private handoff

This file records the user-provided hackathon brief in condensed form so the private mirror retains the governing constraints without exposing personal registration data.

## Challenge

Pick one real problem faced on an Indian public-service website or digital service, then build a simpler, clearer, more useful solution. Examples include travel, taxes, pensions, certificates, payments, and grievances.

## Build requirements

- Solve one clearly defined user problem.
- Complete the main citizen journey from start to finish.
- Be simpler, clearer, and more accessible than the current experience.
- Work for Indian users on mobile, slower connections, and limited digital experience.
- Use mock or synthetic data wherever personal data, payments, OTPs, or government systems would normally be involved.
- Codex or an OpenAI model must be meaningfully involved in the build.
- Reviewers test the citizen experience, not an admin panel.

## Prohibited behavior

- Do not access, test, or interfere with a live government system.
- Do not reverse-engineer private systems or use undocumented private APIs.
- Do not scrape personal or restricted information.
- Do not use real Aadhaar numbers, PAN details, passwords, OTPs, payment details, health data, or sensitive personal data.
- Do not present the product as official government software.
- Do not use official logos in a way that suggests approval or partnership.
- Do not submit code, assets, or data without permission.

## Submission format

- Public browser link with no access request.
- Mock consumer credentials only if the product requires login; never provide a real password or sensitive personal data.
- One public video no longer than two minutes: first minute citizen demo, second minute build and product reasoning.
- Project summary under 250 words.
- Team details only through the official submission form.

## Judging

- Importance and reality of the problem.
- Working end-to-end build.
- Usability and accessibility.
- Product thinking.
- Backend/infrastructure/process thinking.
- Honesty about mocked data and dependencies.

## ApplyOnce interpretation

The canonical citizen problem is repeated re-entry of identity, education, family, address, income, category, certificate, and document data across education and other applications. ApplyOnce demonstrates a synthetic but complete journey: reusable profile → source/provenance → requested scope → explicit consent → internal submission record → receipt and status timeline.

The production direction is broader, but the public hackathon demo remains independent, synthetic, and clear about what is not connected to government systems.
